# 平台与多版本模型

每个项目可同时保留多个已发布版本。发布后的版本内容不可修改；需要变更时创建新版本，例如 `1.4.2`、`1.4.3`。

- Push 任务可以固定到一个已发布版本，或选择“每次最新已发布版本”。
- Pull 节点可以固定 desired version，或开启自动跟随；自动跟随只会推进新的 generation，不会覆盖历史版本。
- 节点按 `server_id` 渲染配置，因此同一制品可用于网关、逻辑服、战斗服和计算节点。
- 回滚应选择已有的已发布版本；不要修改历史制品来伪造回滚。

推荐流程：草稿上传和校验 → 发布不可变版本 → 小范围节点固定版本验证 → 分批推进或开启自动跟随。
