# 平台与多版本模型

express233 的日常流程是：版本包 → 可选分服配置 → 可选配置预览 → 发布版本 → 部署上线。网关、逻辑服、战斗服等独立服务分别建立项目，项目内保留多个版本。

## 发布版本与部署上线

- 草稿用于上传文件、设置文件标签和 VCS 来源。正式版本名使用 X.Y.Z，例如 1.4.3；发布后这些内容不可修改，需变更时创建新版本。
- “发布版本”把包变为可拉取状态。它不等于服务器已经上线；启用的 Release Hook 或 Pull 自动跟随可能随后自动部署。
- “部署最新版本”对当前项目全部明确绑定的 SSH 目标执行部署。最新按 published_at 倒序、同时间按记录 ID 倒序确定，不按版本号大小或版本页当前选择确定。
- 真实 SSH 操作前，主区域和确认框会列出 server_id 与机器名称；自主拉取节点不在本次 SSH 操作内。
- “预演”只解析并记录目标，不连接 SSH、不传包、不停服。预演通过不是部署成功，也不是 SSH 连通检查。
- 进入队列不表示完成。执行后查看逐服状态与输出，并按游戏业务验证登录、数据保存和网关链路。

## 分服配置是共享的可选差异

同租户的 server_id 配置由多个项目共享，配置预览比较原始配置与替换后配置。列表不代表当前项目部署目标；无分服差异可跳过编辑和预览，但实际 Pull / Agent 仍要求对应 server_id 配置条目存在，replacements 可以为空。

发布冻结的是包内文件，不是共享分服配置。修改配置会影响后续拉取；回滚旧版本也使用当前配置和钩子，需重新核对。

## 固定版本、子集与历史数据

高级发布任务可固定某个已发布版本，或每次执行时选择最新；目标可跟随本项目绑定，或固定 server_id 子集。任务标签仍参与筛选，默认 test。“保存并发布”保留子集，保存后确认才执行 SSH；取消确认不撤销已保存的任务。

固定版本被删除或由保留策略清理时，编辑器保留不可用提示，要求明确重新选择，不静默改为最新。回滚要选择仍存在的已发布版本，不修改历史文件。

Pull 节点可固定期望版本或自动跟随。期望版本变化时 generation 增加，Agent 在后续心跳周期执行。单独修改共享配置不会自动产生新 generation。

## 输出和指南入口

部署历史区分“预演”和“部署”。长日志在弹窗内滚动，底部“关闭”与 Escape 可结束查看；关闭不会停止后台部署。运行日志保留 30 天。

公开指南目录为 GET /api/agent/guide；主题为 GET /api/agent/guide/{topic}，返回 JSON 中的 content。可用主题为 overview、agent、gitea、github、security。控制台“文档目录”读取同一份静态内容；不存在独立的 /guide/ 页面路由。
