# 控制台日常发布流程

适用于网关、逻辑服、战斗服等独立服务。每个服务建立一个项目，按“版本包 → 可选分服配置 → 可选配置预览 → 发布版本 → 部署上线”操作。本文适用于 v1.2.x 控制台。

## 先分清三个动作

| 动作 | 结果 | 是否修改游戏服务器 |
|---|---|---|
| 发布版本 | 草稿成为可拉取的已发布版本，文件、文件标签和构建来源锁定 | 发布接口本身不执行 SSH；启用的 Hook 或 Pull 自动跟随可能随后触发部署 |
| SSH 部署 | 中央服把指定已发布版本部署到本项目绑定的 SSH 目标 | 是，需要核对目标并确认执行 |
| Pull 拉取 / Agent | 节点主动下载；Agent 根据期望版本调用本地部署脚本 | 单次拉取负责下载与可选后处理；Agent 调用安全替换流程 |

## 1. 准备版本包

1. 在左侧新建或选择项目。新建后自动进入项目；刷新后会按当前租户和账号恢复仍可访问的上次项目。
2. 在“版本包”新建草稿。界面建议下一个补丁版本，并自动选中新草稿；正式版本使用 `X.Y.Z`，例如 `1.4.3`。
3. 上传文件或压缩包。支持 ZIP、TAR、TAR.GZ / TGZ，归档中的相对目录会保留。确认文件树、启动脚本和文件标签。上传期间切换项目或版本，不会改变这次上传的归属。

同一版本可包含多平台产物，按[文件标签](FILE_TAGS.md)选择性下载。默认上传标签直接可见；批量标签、构建来源和保留策略位于折叠区域。

## 2. 按需填写分服配置并预览

需要不同端口、区服编号等参数时，在“分服配置”选择 `server_id`，按文件修改字段并保存。常见文本、数字和开关保留原类型；原始 JSON、复杂结构和启动钩子在高级入口中处理。

- 配置按租户共享，以 `server_id` 为键，不属于单个项目版本。修改同一个 `server_id` 会影响使用它的项目的后续拉取。
- 共享配置列表不等于本项目的 SSH 目标名单。实际目标在“机器与目标”绑定到项目，并在“部署上线”核对。
- 没有分服差异，可以跳过配置编辑和配置预览；实际 Pull / Agent 仍要求存在对应的 `server_id` 配置条目，`replacements` 可以为空。

在“配置预览”比较“原始配置”和“替换后配置”。这是当前版本按当前共享配置渲染的结果，不是旧版与新版比较，也不会连接 SSH。更换版本、区服或配置后应重新获取预览；获取失败不能沿用旧的确认。

**版本不可变不等于分服配置被冻结。** 回滚历史版本时仍会使用当前共享配置，因此应同时核对配置与启动钩子。

## 3. 检查并发布版本

进入“发布版本”，执行“发布前检查”，在当前页面查看错误和警告。空版本包、重名配置文件等问题应先修复；共享配置引用其他项目的文件可能产生警告，需结合当前项目判断。检查不运行游戏服务，也不运行浏览器 E2E。

点击“正式发布”后，版本包文件、文件标签和 VCS 来源不可再修改。需要调整时新建版本。发布前同时确认是否启用了自动 Hook 或 Pull 节点自动跟随，这些规则可能在发布成功后自动部署。

## 4. 部署上线

常规 SSH 操作使用“部署最新版本”。“最新”按 `published_at` 倒序确定，同时间按版本记录 ID 倒序；不是版本号最大、创建时间最新，也不是版本页当前选中的版本。

1. 核对主区域显示的版本、每个 `server_id`、机器名称和备份策略。
2. 可先“预演”检查解析出的目标名单。预演只做目标解析，不连接 SSH，不验证机器连接、磁盘、启动或业务健康，也不更新机器的最近部署版本。
3. 点击“部署最新版本”，再次核对确认弹窗中的完整 SSH 名单，再确认执行。自主拉取节点不在本次 SSH 操作内。
4. 在执行结果中查看逐服状态。进入队列不代表完成；“预演通过”也不等于“部署成功”。正式部署默认串行，Linux 脚本按预拉取、备份、正常停服、替换、启动与检查执行，详见[安全部署](SAFE_DEPLOY.md)。

“机器与目标”的连接检查用于验证 SSH 连接与认证，和部署预演用途不同。即使部署脚本成功，游戏登录、玩家数据与网关链路仍需按业务验收。

## 固定版本、固定区服与回滚

展开“高级发布任务”，只在需要这些策略时创建任务：

- **版本**：选择一个已发布版本，或每次运行时取最新已发布版本。部署旧版用于回滚；不要修改历史包。
- **范围**：跟随当前项目绑定，或明确填写固定 `server_id` 子集。任务还会按发布标签筛选，默认标签为 `test`；固定子集不绕过标签过滤。
- **执行**：“保存任务”只保存定义；“保存并发布”保留当前固定子集，保存后仍需确认才执行 SSH 部署。取消确认不会撤销已保存的任务。

高级任务中的“发布”指执行 SSH 部署，不是把草稿发布为版本。固定目标不能为空；历史固定版本被删除或清理后，会保留不可用提示，要求显式选择另一个已发布版本或“最新”，不会静默改成最新版本。

保留策略可能清理已发布包，部署任务和节点引用不会替你保留它们。设置保留数量前确认仍需使用的回滚版本；包不存在时必须先恢复可用版本或调整策略。

## 日志与自动规则

“部署历史”会区分预演和真实部署。打开“查看逐服输出”可阅读长日志；内容区域独立滚动，底部“关闭”按钮保持可见，也可按 Escape 关闭。关闭弹窗只结束查看，不取消后台部署。执行、目标输出、Hook 事件、Pull 与审计日志统一保留 30 天。

Release Hook 默认在最后一次触发后等待 30 秒，合并等待期间的发布事件，并部署最后触发的版本。上传文件本身不触发 Hook。Hook 沿用关联任务的目标范围和标签，使用触发事件的版本；如果希望始终固定某版本，应使用手动任务并关闭该自动规则。

Pull 节点可固定期望版本或开启自动跟随。需要分批上线时，先明确小范围目标并验证，再逐批执行；平台不会根据标签自动生成灰度波次。协议和状态含义见[统一交付控制平面](DELIVERY_CONTROL_PLANE.md)。
