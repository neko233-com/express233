# 控制台日常发布流程

适用于逻辑服、网关、SDK 服等独立服务。每个服务建立一个项目，版本包和部署目标按项目隔离。

1. **版本包**：新建版本会自动选中新草稿。上传文件或 ZIP，页面显示进度；版本号自动建议下一个补丁版本。
2. **发布版本**：通过“下一步”进入检查页，检查结果直接显示在当前页面。发布会锁定文件；已启用的自动发布规则可能触发部署。
3. **部署上线**：点击“部署最新版本”前核对版本、逐个 server_id、机器名称和备份策略，确认弹窗会再次显示目标名单。最新版本按发布时间确定；自主拉取节点不参与本次 SSH 操作。

**预演只核对目标。** 页面明确区分“预演通过”和“部署成功”。预演不会连接 SSH、更新服务器或覆盖节点的最近部署版本；进入队列也不代表部署完成。

**分服参数是可选项。** 需要不同端口或区服编号时，进入“分服配置”按文件填写参数，再预览替换后的内容。配置以租户内的 server_id 共享，同一 server_id 的修改会影响使用它的项目。文本、数字和开关保留各自类型；完整 JSON 与启动钩子位于高级入口。

**低频工具按需展开。** 批量文件标签、构建来源、保留策略、固定目标任务、自动 Hook 和部署历史仍然可用。已发布文件只读；修改请创建新版本，历史版本回滚通过高级发布任务指定版本。

固定目标任务在“保存并发布”时保留选定的 server_id 子集。固定版本已被清理时，页面会要求明确重新选择版本，不会自动改为“每次最新”。配置预览中的共享 server_id 列表不代表项目部署目标，左右分别展示原始配置和替换后配置。

**交互保障。** 创建项目后直接进入工作区；上传绑定发起时的项目和版本；改变预览条件后必须重新获取预览。新手引导由用户主动开启。

验证包含独立本地实例的浏览器全流程、配置类型保留、上传切换版本隔离、发布检查反馈和窄屏布局；真实游戏服启停属于每次部署的业务验收，不能以控制台测试代替。
