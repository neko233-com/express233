express233 使用文档

一个中央控制台维护多项目、多版本、多平台制品，并按 server_id 做嵌套配置替换。它统一 Pull Agent 与 SSH Push 发布，并将制品内容摘要、Git/Gitea/GitHub 提交和构建运行固化为可审计快照。

开始使用 查看 OpenAPI 进入仓库
express233 控制台root

1. 启动与登录

本地调试推荐直接运行项目自带脚本。它会启动中央服并监听 127.0.0.1:23380。

run-server.cmd

首次部署到服务器时，先使用 root 账号进入系统设置创建日常账号。控制台会使用 JWT 和 HttpOnly Cookie，401 会自动回到登录页。

登录后先做三件事

创建项目，配置 server.yaml，上传第一个版本包。新手引导可以跳过，系统会记录已引导状态，后续也可从左下角重新打开。

2. 项目与版本

01左侧创建项目
02版本页新建版本号
03上传文件或 zip 包
04设置平台标签
05预览后发布

版本列表支持搜索、历史回滚和固定版本。已发布版本（包括文件标签与 VCS 溯源）不可修改；修复必须创建新草稿，避免同一版本号对应不同生产字节。

3. 制品与 VCS 溯源

每个版本草稿可绑定 Git、GitHub 或 Gitea 的仓库 HTTPS 地址、ref、commit、构建运行 URL/ID。发布时服务端对排序后的每个文件路径、权限、大小和 SHA-256 计算不可变制品清单摘要；它不依赖上传时使用 zip、tar 还是逐文件。

{
  "name": "4.3.0",
  "vcs": {
    "provider": "gitea",
    "repository": "https://git.example.com/game/server",
    "ref": "refs/tags/v4.3.0",
    "commit": "0123456789abcdef",
    "run_url": "https://git.example.com/game/server/actions/runs/42",
    "run_id": "42"
  }
}
供应链边界

仓库和运行链接只接受无凭据 HTTPS URL；commit 必须是 7–128 位十六进制。CI 二进制产物额外携带 PROVENANCE.json 与 SHA256SUMS，方便离线验证和导入。

4. 多平台文件标签

一个版本可以同时上传 Windows、macOS、Linux，x86_64、arm64 等所有二进制。下载方上报自身环境后，服务端只返回匹配标签的文件。未设置标签的文件等价于 *，所有平台都会下载。

上传文件树预览
bin/game-linux-amd64linuxamd64
bin/game-linux-arm64linuxarm64
bin/game-windows-amd64.exewindowsamd64
config/default.yaml*

推荐标签规范

维度建议值说明
系统windows mac linux按下载方操作系统过滤。
架构amd64 arm64按 CPU 架构过滤。
用途server tool可选，用于自动化运维选择不同文件组。

5. 配置替换预览

配置替换不是 key/value 列表，而是路径树、原文件、替换后文件三栏预览。左侧选文件，中间看原始内容，右侧看按 server_id 替换后的内容，修改行会高亮。

server.yaml 示例

replacements:
  game.yaml:
    s1:
      db_host: 10.0.0.11
      listen: 0.0.0.0:7001
    s2:
      db_host: 10.0.0.12
      listen: 0.0.0.0:7002

替换原则

replacements 的 key 是配置文件 basename，也就是 game.yaml，不要求写完整目录。发布前必须在“拉取预览”确认文件树和 diff。

6. Push / Pull 交付与自动化

Pull Agent 以最小权限 Token 或 Basic Auth 心跳并收敛 desired version/generation；Push 使用已固定 Host Key 的 SSH 资源和可重复发布任务。两种模式共用版本、配置渲染、审计与集群节点清单。

# 典型节点流程
pull 到 GAME_ROOT/.tmp/{server_id}/
停止 GAME_ROOT/{server_id}/run/server.pid 对应进程
rsync 临时目录到正式目录，保留 logs/ 与 run/
执行 scripts/restart.sh

Release Hook 可选择开启，默认在 30 秒尾随窗口合并多个触发为一次最新版本发布；Pull 节点可选择自动跟随。日志、Hook 事件与发布输出默认保留 30 天。

7. 自动化 HTTP 操作

Agent 或运维脚本可以使用 API 做批量标签、上传、预览、VCS 溯源和发布。接口以 OpenAPI 为准；公开 /api/agent/guide 仅返回官方脱敏接入说明。

# 查询 OpenAPI
curl -fsSL https://neko233-com.github.io/express233/openapi.yaml

# 下载节点建议上报信息
server_id=s1
os=linux
arch=amd64
tags=linux,amd64,server

批量运维建议把平台标签作为机器画像的一部分，避免跨平台二进制被错误拉取。

8. 数据大盘与运维建议

弱网优化

优先上传 zip 产物，服务端按文件标签选择性下载。zip 内部已压缩的二进制再 gzip 收益有限，重点应放在断点重试、校验和、分平台过滤。

版本治理

用 VCS commit + 制品清单摘要证明生产字节来源；一个大版本只维护一个多平台包，标签决定下载范围。

快速定位

ECharts 大盘显示按日上传、拉取、SSH 发布和失败压力；实时卡片显示 Pull 漂移、SSH 健康和 Hook 积压。
