# 制品存储策略

Express233 默认使用本地制品存储。对象按 SHA-256 去重，放在 `<dataDir>/blobs/<摘要前两位>/<摘要>`。SQLite 管理引用和制品元数据。版本树仍位于 `<dataDir>/userdata/<tenant>/projects/<project>/<version>/`，已有数据升级时继续使用这两个目录。有硬链支持时，本地策略会复用内容，其他情况下按流复制。

上传时先把文件流写入暂存文件并计算摘要。对象存储完成后才原子替换版本文件。重复内容共享引用，最后一个引用释放后才清理对象。清理失败会保留零引用记录，管理员仍可在存储页执行关联检查并重试。发布、预览、下载、Pull 和 Push 继续使用原有 API 和版本目录。

## 接入其他存储

`internal/store` 的 `BlobStorage` 定义了稳定的策略名称，以及按摘要原子写入、流式读取、幂等删除的契约。使用 `OpenWithBlobStorage(dataDir, backend)` 注入实现。测试通过替代策略覆盖了去重、覆盖失败保留旧内容、回收失败后重试，以及防止误用另一个策略打开已有制品。

未来可为 S3 实现该接口。单个数据目录绑定一个策略名，跨策略迁移需要按摘要复制并校验对象后切换。当前发布使用本地策略。SQLite、租户配置和用于现有部署流程的版本文件投影仍由本机持久化管理。
